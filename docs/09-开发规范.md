# 开发规范

## 1 分支策略

| 分支 | 用途 | 说明 |
| --- | --- | --- |
| `main` | 稳定可交付版本 | 只接受通过测试的合并，每个里程碑打 tag |
| `dev` | 日常集成 | 功能完成后并入，定期合入 main |
| `feature/<名称>` | 单个功能 | 如 `feature/trace-service`，完成后并入 dev |
| `fix/<名称>` | 缺陷修复 | 从 main 拉出，修复后合回 main 与 dev |

版本标签：`v0.1-开题`、`v0.5-模型完成`、`v0.8-系统联调`、`v1.0-答辩`。

## 2 提交信息

采用 Conventional Commits：

```
<类型>(<范围>): <简述>

类型：feat | fix | docs | test | refactor | chore | perf
范围：data | model | api | web | docs | config
```

示例：

```
feat(api): 新增预测接口与错误码约定
fix(model): 修正输入窗口切片导致的标签泄漏
docs(docs): 补充数据库字段字典
test(api): 补充分级接口异常用例
```

要求：一次提交只做一件事；涉及行为变更须在正文说明原因与影响。

## 3 代码规范

**后端（Python）**
- 格式：black（行宽 100）+ ruff 检查
- 命名：模块 snake_case，类 PascalCase，常量 UPPER
- 类型注解：公开函数必须有类型标注
- 禁止在 `api/` 中写数值计算（见概要设计决策 1）

**前端**
- ESLint + Prettier，组件文件 PascalCase
- 状态集中在单一 store，视图不互相调用
- 接口调用统一封装在 `src/api/`

## 4 测试要求

| 变更类型 | 最低要求 |
| --- | --- |
| domain 层计算 | 新增函数必须有单元测试 |
| 接口 | 新增或修改必须有接口测试 |
| 前端交互 | 关键路径有端到端用例 |

合并前本地跑通：`pytest -q`、`npm run lint`。

## 5 目录与文件约定

```
src/
├── data/       数据读取、清洗、特征
├── models/     ModelAdapter 实现、训练与推理
├── domain/     指标、网络统计、忠实度（纯函数）
├── api/        路由
├── service/    用例编排
├── infra/      DB、缓存、模型加载
└── web/        前端工程
```

新增文件必须落在对应目录，不允许在根目录堆放脚本；一次性脚本放 `scripts/` 并注明用途。

## 6 文档同步

- 接口变更：先改 `docs/05-接口说明.md`，再改代码；
- 数据字段变更：同步 `docs/07-数据说明.md`；
- 实验参数变更：写入 `configs/` 与 run 的 config.json，不改代码常量。

## 7 Issue 模板（建议）

**缺陷**：现象 / 复现步骤 / 期望结果 / 环境 / 日志
**功能**：背景 / 目标 / 验收标准 / 关联用例编号

## 8 提交前检查清单

- [ ] 没有把数据、权重、token 提交进仓库
- [ ] `git status` 中无意外文件
- [ ] 相关文档已同步
- [ ] 测试通过
